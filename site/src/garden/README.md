# 庭间 · 枯山水

一间小屋，一家人，一座慢慢被照料的时间庭院。

当前版本：**1.6.0**。这次集中减少修复中的多余动作：先检查真实沙槽是否受损，再把同一站位能够完成的缺口连成完整笔画；重复划过的区域和动物足迹使用更紧凑的清扫路线。交班在接手下一批工作之前检查，低帧率时也保留前台实际经过的时间。继续保留沿外围绕行、内部入口收尾、逐颗搬运时石、环绕森林、安静来访和真实足迹。

这个版本把原来的二维时间花园重建为可以环绕观察的三维庭院。沙纹、访客划痕、动物留下的小印记和家人的整理动作，共享一份持续保存的沙面；时间和天气的变化不会重新生成石头、沙盘或人物位置。

## 直接打开

打开 `dist/karesansui_v6.html`，或单独下载成品 HTML 后用浏览器打开。无需启动服务器、安装依赖，也不需要在线下载模型、图片、字体或脚本。推荐使用支持 WebGL 2 并开启硬件加速的 Chrome、Edge 或 Safari。手机如果从文件管理器只能看到源代码，可把同一 HTML 放到网站后用浏览器访问。

成品可作为独立页面部署，也可通过网站的 iframe 集成。设置 iframe 的 `width:100%`，并给它明确高度，例如 `height:100dvh; border:0`。源码中的中文界面集中在 `shell.html` 和 `src/main.js`，便于接入网站已有的语言系统。

部署时直接上传构建好的 HTML 即可；只有修改源码后才需要重新构建。网页沿用简洁的中文界面，新增家人、动物和照料行为没有增加说明面板或操作按钮。

## 时间怎样留在沙上

- 螺旋由内向外延伸。每绕一圈代表一小时；一条耙痕内部有五道细槽。
- 外圈石头表示已经走到的小时，沿顺时针依次摆在 1—12 点位置。14:05 和 14:59 都是两块；15 点后开始搬第三块。尚未摆入的石头放在屋旁木台上。
- 采用十二小时制：00 点和 12 点都是十二块；进入 1 点后，保留第一块，其余从后往前逐颗搬回木台。这个收回过程与沙纹的正午／午夜整理是两个独立的物理任务，不会清空画面。
- 庭院按十二小时一个周期照料。正午、午夜或大幅跨期后，家人会实际走到旧沙纹旁，逐圈整理，再刻出新周期；旧纹不会整片消失。
- 访客可以在空白处或已有纹路上划沙。负责修复的家人会先把被扰动的区域抹平，再恢复应有的时间沟槽，并把这一处的收尾工作连续做完。
- 这是一座有工作过程的时间庭院。刚回来、密集划沙或换周期时，沙上的记录可能暂时落后于真实时间。右上角小钟始终显示浏览器的本地时间。
- 天光面板只改变光线、天气与时节的预览，不改变计时目标，因此浏览清晨或夜晚不会重排沙纹。

## 家人如何照料庭院

一家人共有阿婆、妈妈、爸爸、姐姐、妹妹和弟弟。不同人物有自己的身形、发型和衣服：阿婆戴眼镜，妈妈系围裙，爸爸戴草帽，姐姐扎马尾，两个孩子有单独的头身比例及小工具。

同一时间最多只有一位家人在外面。前一位完全走回屋内后，下一位才会出门；成人轮流照看时间和修复沙面，孩子只在庭院较空闲时出来整理边缘。孩子会实际平沙，并在完成后回屋休息。人物通过门廊出入，交班和离开都有完整的行走过程。

成人出门满约三分钟后，在当前这批清理和补纹收尾时交班，下一批由下一位接手。不会因为队列又出现新工作而不断续班；也不会把尚未完成的内圈入口留给下一人。复杂维修可能超过三分钟，空闲时也会提前回屋。搬石头同样在每颗石头放稳、人物站直之后检查交班。前一位进入屋内后，再留出约三秒间隔安排下一位。

人物采用较柔和的头身比例和衣袖轮廓。行走时单手把工具拿在身侧，空闲的手臂随脚步摆动；转身、停步和工作之间有连续过渡。工具保持固定长度，工作时通过调整握持和站位触及沙面。猫、兔子和麻雀分别使用四足行走、跳跃和短促跳步，停留时也保留轻微的观察动作。

### 取石、搬运与放置

家人先完成当前这一处的沙面修复，再回屋放好耙子，开始一趟需要双手的搬运。走到石架前蹲下，双手托起石头，沿外圈安全路线搬到对应时位，然后慢慢降低石头、松手并站起。搬运时收小步幅，身体与视线随着负重调整；脚底仍使用同一套真实沙面净空检查。

屋旁、手上和钟圈里的始终是同一批十二块石头。每块形状、尺寸和身份固定；取起后才移除地面的碰撞体，放稳后才加入新的碰撞体。石头不能隔空出现，也不会在一帧里切换布局。搬运途中出现新的划痕，会寻找实际可走的绕行路线；手指穿过搬运者时，人物脚下的区域被身体挡住，露出的沙面仍可以划动。

整点只更新待办目标。改时间时，已经抱起的石头会先完成当前这一趟，再根据最新小时继续摆入或收回，不会中途从手上消失。当前石头数量会因搬运耗时短暂落后；大量回拨、十二点后的逐颗回收、旧版十二颗布局迁移，需要更多时间。首次建立新庭院时，会按当前小时摆好已经走过的石头。

### 绕行、临时通道与修复收尾

家人走路时会检查脚下的真实沙面，为自然步幅留出完整的落脚区域，优先选择避开完整沟槽和石头的路线。规划余量不足时，会进一步检查实际脚掌能否安全通过；所有路径仍逐段验证，没有缩小人物脚部。途中新增脚印让原站位失效时，舍弃旧站位重新寻路，同时保留工具已经完成的进度。工作前检查整段工具轨迹是否可达，尽量站稳完成手边的一段，减少在沙纹末端来回换位置。第一次巡视停留在屋前外圈，不会为了巡视就拆开完整沙纹。

损坏发生在另一侧时，先检查那一侧能否从外围抵达，而不是只检查离当前人物最近的几个站位。能够绕到的边缘划痕，沿完整外围步行过去修复。站位和接近路线一起比较：少影响已有沙纹优先，其次才是行走距离。

密集的螺旋有时会把内侧作业点围住。如果确实没有可走的通路，家人先绕到合适入口，再用平沙板整理一条局部小径，沿已经整理的位置前进。入口同时考虑接下来计时沙纹的延伸方向，保留往返工作的空间。平沙板在画面中实际接触沙面，规划本身不会修改高度场。

划痕、抚平时受到影响的相邻沟槽，以及临时小径影响到的时间纹路，都属于同一位家人的修复责任。普通平沙带也可能成为返回时要走的通路，因此会和专门开辟的小径一起保留首次整理顺序；后续再次清理同一位置，不会把入口抬到内部缺口之前。每补一段前，还会检查其余未完成位置是否仍有能走到、能伸耙作业的站位；如果这一段会封住另一个作业点，就先处理那个位置，再回来收口。顺序由真实通路决定。

可能碰到沟槽的清扫范围只用于筛选候选。1.6 会把五道细槽及中间槽脊的真实高度与应有沙纹比较；仍然完整的部分无需抬耙重画。这份比较数据只供判断，不参与画面显示，也不能修改实际沙面。

选择补纹站位时，优先查看当前脚边已经能够完成的工作。相邻缺口如果属于同一批、工具够得到，并且保留退路和其他作业点的入口，就连续画完；较短整弧会额外尝试一个能够覆盖整段的站位。只有确实需要绕过石头、超出触距或保护内部入口时才分段。狭窄位置会继续搜索实际可站的小范围，避免主体已经画完后再绕回来补一个小尾巴。补纹时保持选定站位，工具仍按正常速度接触沙面。

每批修复在接手时固定损坏范围，同时负责补回本批平沙与通行实际影响到的沟槽。新出现、与这一处无关的划痕留在下一批，避免当前工作无限扩张。既有的零散时间缺口在批次之间接管。补纹前检查整段工具触距、脚下净空和可用退路；深处尚有缺口时，入口不会因为暂时画不了那一小段就被提前封住。确认这一处收尾完成后才回屋休息。

计时不会一直排在所有修复之后。维修期间，目标时间落后约 90 秒时，会在一小段工作完成后寻找安全站位补画时间。长距离清扫也能在抬耙处暂停，保存剩余路线；到了沙纹末端，会把能补的进度接着画完，再沿保留的通道返回原工作处。预留区域按实际平沙板宽度计算，避免刚画好的时间又被未完成的宽板清扫擦掉。入口受阻或换周期时，实际等待仍受物理行程影响。

如果访客在正在修复的地方又划一笔，耙子会在触及新划痕之前停下抬起，等待这次输入结束后先平沙，再恢复沟槽。待清扫区域的保护范围会预先采用实际清扫路线、平沙板宽度和短划痕的端点范围，避免先补好其边缘，又被紧接着的清理擦掉。已经整理的退路突然被划断时，先检查局部清理能否恢复原路；确认可行后，只处理阻路的那一小段，沿原路继续工作。手指还在划动时会等待。直接阻挡计时末端或内部收尾的新损坏，也只接手必要的局部范围；同一只动物在远处留下的其他脚印仍留在后续批次。其他新增工作不会随时抢走当前目标。待办超过两分钟后按最早出现的顺序接手，避免远处的旧划痕一直被附近的新工作插队。

内圈密集修复、大面积划沙和更换十二小时周期，都需要更多绕行、平沙和补刻，处理时间会长一些。连续制造新的划痕也会增加待照料的工作量。

“靠近看看”会根据当前人物与手中石头选择正面或侧前方的观察角度，并避开屋檐和景石。仍可继续自由拖拽环绕，不会锁住视角。

## 林间的小动物

猫、兔子和两只麻雀会从周围树林进入庭院，停留一会儿，再离开。本版缩小了动物相对庭院和人物的体型，并同步调整步幅、速度、脚印和避障范围。猫的身体与尾巴连接更连贯，兔子采用圆拱背部和收在躯干旁的后腿；猫迈步时保留支撑脚，兔子和麻雀主要在跳起阶段前进，落地时短暂停顿。

庭院空闲时，第一次自然来访会等候约 45–90 秒。之后一次只安排一只动物，等它完全走回树林，再安静至少 3–5 分钟。若仍有划痕或修复没有收尾，下一次自然来访继续等候；当前这批照料完成后，还会留出 20 秒安静时间。已经出现的动物照常走完本次来访、留下真实脚印并回到树林。这使一位家人有机会完成当前工作，庭院也能恢复平静。

猫和兔子在进入、闲逛、后退和离开时，实际支撑脚的新落点都会留下足迹；麻雀落地、啄沙时也会造成小小的凹痕。脚印额度不再在入口几步就用完。痕迹与实际脚掌、爪子或喙的接触位置对应，抬起时不会提前写到沙上，同一只脚静止压着同一处也不会反复制造新印记。动物印记与手动划沙一样，会改变真实的沙面，并进入家人的整理流程。

家人把邻近足印连成连续清扫行程；在石头旁从外侧沿弧线整理。边缘小修补使用较窄的平沙板，长距离行走清扫使用足以留下可走地面的宽度，画面中的工具与实际作用范围保持一致。每个原始落点的覆盖范围都保留，改变的是未来怎么扫，不会先删除或抽掉可见脚印。这样不必为了每个几毫米长的小印记反复抬耙、落耙、换站位。清理扫到的时间纹路仍会登记，并在同一趟工作中补回。

1.6 让相邻清扫行程充分使用平沙板的有效宽度，并比较不同起始位置，减少覆盖同一条足迹两次的情况。访客在同一区域反复来回划动时，也会把重复覆盖合并为完整整理路线；普通短划痕仍沿原有笔画处理。合并前后都保留每个实际落点的覆盖范围，石头内部始终不允许清扫。

同一只动物在一次来访中留下的足印按同一来源记录，停止新增足印约 10 秒后再安排这一批清理，避免园丁追着正在走动的动物一路抹沙。

每次来访的停留和行程有限，动物最终会自行离开。它们会避开房屋、石头，家人靠近时也会警觉或退开。动物行为与天气一样属于艺术化模拟，没有尝试复现真实生态系统；它们的节奏服务于这座安静的小庭院。

## 场景与光线

三维庭院包含灰瓦木屋、滑动纸门、门廊、简单室内陈设、石灯、手水钵、苔藓、踏石、竹篱以及环绕树林。石头和植被由固定种子创建，天气和窗口大小都不改变它们的位置。人物有手脚关节、支撑脚落地的步态及握耙约束；刻线时耙齿沿既定轨迹移动，清理时使用翻转后的整平面。

相机可以环绕整个庭院。近景树丛之外新增三层固定远林和林下植被，覆盖最远观察距离；外地面向树林深处延伸，降低视角也不会露出原来的方形地面边。镜头和庭院之间的近处枝叶会柔和避让，远处森林保持完整。手机和桌面保留相同的树林位置，手机减少几何细节；这些内容复用内嵌材质，不增加在线下载。

沙槽的凹处阴影和槽沿明暗取自实际高度场，因此时钟、访客和动物的痕迹使用同一套显示方式。夜间会连续增强细槽的辨识度；远处的细纹使用多级纹理过滤和斜视角过滤，减少视角变化时的闪烁与摩尔纹。改变天光只调整显示，沙面的物理记录保持原位。

光照随浏览器本地时间连续变化。太阳方位使用温带北半球的艺术化近似；天气和季节来自程序模拟，没有定位权限、真实天气接口或网络请求。清晨有露光，雨天表面逐渐湿润，冬季可以飘雪，夜间小屋和庭灯点亮；暖季夜晚可能出现萤光。天气不侵蚀已经记录的沙纹，以维持时间与互动的连续性。

## 保存与恢复

页面会把当前沙面、待处理的划痕、计时进度和正在执行的工作保存在浏览器的 IndexedDB 中。当前家人的位置、任务归属、临时通道及其收尾顺序、每块时石的位置与归属、手上的石头和搬运阶段，以及动物本次来访的状态也会一起保存。定期保存，并在划沙结束或页面失去可见性时尝试保存。重新打开同一浏览器和同一文件／网站位置，会接着照料已有庭院。

保存属于当前浏览器环境。浏览器清理网站数据、隐私模式或改变文件地址后，可能无法读取之前的庭院。浏览器强制关闭、进程崩溃时，最后一小段未完成写入的操作可能来不及保存。

世界存档沿用 `format: 2`，当前照料版本为 `careVersion: 2`。此前的单人存档仍可读取。读取 `careVersion: 1` 的多人存档时，会在第一帧显示前保留一位工作人员，合并其他家人尚未处理完的清理任务与修复归属；沙面和保留者的位置不变。恢复后的庭院遵循一次只出一人的规则。动物状态作为独立字段随整个庭院存档保存。

1.3 会为旧版正在进行的修复建立新的后续顺序：人物、工具、当前任务进度、路线和沙面保持原样，旧版因反复开路而抬高的错误优先级不再继承。动物调度使用 `scheduleVersion: 2`；旧存档里如果已有多只动物在外，它们会各自沿原路继续离开，再进入一次一只的安静来访节奏，不会在读取时突然消失。

1.4 新增独立的 `hourStones.version: 1` 状态。读取没有该字段的旧存档时，保留原来十二块石头的精确形状和位置，再由家人逐块搬回多余的石头，因此不会刚打开就从十二块跳成两块。新版可在蹲下取石、途中搬运或低头放置时保存；回读保留同一块石头和当前动作阶段。

1.5 新增 `workPlanningVersion: 1`，保存当前维修批次、通道、接近路线、暂停清扫的完整剩余路径、补画时间的往返状态和最近收尾时间。旧存档读取时保留现有沙面、人物及工具姿态，在后续正常动作中使用新的选路和工作规则。

1.6 沿用现有存档格式。前台卡顿或帧率下降时，尚未处理的时间保留在累计器中，以不超过 0.05 秒的小步继续推进工作；每个显示帧只提交一次沙面纹理与环境显示。隐藏、暂停后不会补跑离开期间的动物和人物动作；超过三十秒的浏览器或系统挂起会明确作为恢复处理，并重新读取当前目标时间。大幅离线回来后的沙面仍由人物实际照料。

沙面以固定精度量化保存，回读只产生微米级误差。保存不会通过截图或分层贴图累计历史，因此长时间互动不会不断增加整张画布。

## 重建

使用 Node.js 20 或更新版本，在这个目录运行：

```bash
npm install
npm test
npm run build
```

构建会生成单个 `dist/karesansui_v6.html`。依赖版本固定为 Three.js `0.180.0`、esbuild `0.25.10`。依赖只在开发和构建时安装；成品运行时没有 CDN 请求。

### 验证

`npm test` 执行当前项目配置的回归套件，具体入口见 `package.json`。需要单独排查某一部分时，可以运行：

```bash
node qa/care-regression.mjs
node qa/stall-check.mjs
node qa/inner-repair-check.mjs
node qa/return-access-check.mjs
node qa/family-motion-check.mjs
node qa/navigation-clearance-check.mjs
node qa/surface-index-check.mjs
node qa/traffic-check.mjs
node qa/wildlife-tests.mjs
node qa/wildlife-world-contact-check.mjs
node qa/animal-maintenance-check.mjs
node qa/maintenance-motion-check.mjs
node qa/forest-geometry-check.mjs
node qa/lifecycle-check.mjs
node qa/living-garden-check.mjs
node qa/input-audit.mjs
node qa/hour-stones-check.mjs
node qa/hour-stone-animation-check.mjs
node qa/close-view-check.mjs
node qa/work-planning-check.mjs
node src/sand_check.mjs
```

照料和导航检查使用真实世界调度及沙面数据，验证任一时刻最多一人、脚步净空、同一事件的连续修复、家人实际平沙、时间切换时的连续性，以及工作中途的存档恢复。卡住回归会在工作中主动把新划痕画到人物脚边，并检查同一趟出门能否完成剩余工作。动作检查验证步态与接触约束；动物检查验证有限来访和可被整理的真实印记。沙面检查覆盖五齿沟槽、重复写入边界、统一整平、固定缓冲和量化恢复。

`qa/browser-regression.cjs` 使用 Playwright 检查完整页面。若在自己的环境运行，先执行 `npm install --no-save playwright` 和 `npx playwright install chromium`，再执行 `npm run build` 与 `node qa/browser-regression.cjs`；脚本会自动寻找当前项目和浏览器。也可通过 `GARDEN_PROJECT_ROOT`、`GARDEN_CHROMIUM`、`GARDEN_PLAYWRIGHT` 指定已安装的位置。

报告记录的是具体构建和环境的一次运行结果，应在修改后重新生成。逻辑检查与浏览器画面检查各有范围；软件渲染环境中的启动时间或帧率也不能直接代表真实手机或显卡的表现。

## 调试入口

页面提供 `window.__GARDEN__`，供开发时检查：

```js
__GARDEN__.snapshot();
__GARDEN__.pause();
__GARDEN__.pause({ render: false }); // 暂停绘制，便于固定帧检查
__GARDEN__.advance(10, { render: true });
__GARDEN__.resume();
__GARDEN__.setEnvironment({ hours: 7.5, weather: 'clear', season: 0 });
__GARDEN__.setTime('2026-10-20T00:00:00');
__GARDEN__.useLiveTime();
__GARDEN__.world.workers; // 当前工作人员：空数组或只有一人
__GARDEN__.world.hourStones.snapshot(); // 目标小时、已放入数量、手上石头
__GARDEN__.world.hourStones.stones; // 十二块石头各自的物理状态
__GARDEN__.wildlife.snapshot();
__GARDEN__.wildlife.invite('cat'); // 调试来访：cat / rabbit / sparrow
await __GARDEN__.persist(true);
```

调试邀请仍会让动物从林间走进来，遵循同一套行走、接触和离场规则。它只用于开发检查，页面没有额外的动物控制按钮。

URL 加 `?fresh=1` 可以临时忽略存档进行测试；它不会删除原来的存档。`?quality=low` 使用较轻的显示质量。页面不提供开发用时间跳转按钮，避免给日常观察增加文字和控件。
